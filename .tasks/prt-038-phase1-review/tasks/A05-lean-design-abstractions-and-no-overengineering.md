# Aspect A05: Lean Design, Abstractions, and Anti-Overengineering

Цель:
- проверить, не уводит ли текущий протокол систему в ненужную сложность;
- найти premature abstractions, лишние слои, лишние сущности, лишние сервисные разрезы;
- оценить, где стоит удержать решение максимально простым и бережливым.

Что смотреть:
- весь пакет `PRT-038/039/040`;
- `ADR-005`;
- `three-layer-product-line-architecture.md`;
- product-local protocols;
- любые места, где упоминаются будущие сервисы, shared UI, shared DB, generalized import model, control plane centralization.

Что искать:
- абстракции без реального второго потребителя;
- сущности или подслои без доказанной пользы;
- “готовность к будущему”, которая усложняет первую волну;
- места, где можно обойтись shared contract + local implementation, но формулировка протокола может спровоцировать лишнюю централизацию;
- неявные призывы к созданию нового shared service/product без достаточного основания.

Особый фокус:
- source-processing service;
- global control plane;
- universal RBAC;
- слишком богатые shared object models;
- преждевременное выносение UI во framework layer.

Ожидаемый отчет:
- перечень мест, где протокол уже бережлив;
- перечень мест риска по overengineering;
- конкретные формулировки, которые лучше ужесточить ради простоты;
- что сознательно не делать в phase 1;
- какие паттерны здесь являются лучшими практиками именно из-за их простоты.
