# Пробелы и риски

- В shared протоколе нет явной state machine для `ImportRun`/`SourceRevision`: lifecycle перечислен шагами, но transition-модель `create/validate/review/approve/activate/fail/retry/rollback` не зафиксирована как контракт ([PRT-040](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/plans/protocols/PRT-040-governed-content-source-processing-and-workflow-backed-import-substrate.md#L111), [PRT-040](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/plans/protocols/PRT-040-governed-content-source-processing-and-workflow-backed-import-substrate.md#L159)). Риск: каждый продукт введет свой state graph без совместимой карты.
- Критичный handoff “extraction bundle -> product importer” описан только концептуально: нет минимального request/response контракта с ownership полями и failure envelope на shared уровне ([PRT-040](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/plans/protocols/PRT-040-governed-content-source-processing-and-workflow-backed-import-substrate.md#L113)). В Docoved это уже формализовано локально, но не поднято в общий минимум ([docoved ingest architecture](/Users/deksden/Documents/_Projects/docoved-agent/.memory-bank/spec/architecture/domains/docoved-agentic-ingest-and-knowledge-projection-model.md#L208)).
- Capability vocabulary shared-слоя не покрывает import/review/activation actions: в `PRT-039` есть `pipeline_binding.manage`, но нет семейства прав для `import_run.start/review/approve_activation`; Docoved уже добавляет это локально ([PRT-039](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/plans/protocols/PRT-039-shared-control-plane-access-channel-and-management-substrate.md#L88), [Docoved PRT-038](/Users/deksden/Documents/_Projects/docoved-agent/.memory-bank/plans/protocols/PRT-038-docoved-shared-platform-adoption-control-plane-and-workflow-backed-knowledge-import.md#L104)). Риск: несовместимые authorize-паттерны между продуктами.
- Для `Channel`/`PipelineBinding` есть поле `binding_status`, но нет допустимых статусов и переходов (включая rollback при несовместимом pipeline/policy change) ([PRT-039](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/plans/protocols/PRT-039-shared-control-plane-access-channel-and-management-substrate.md#L126), [pipeline-registry spec](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/spec/runtime/pipeline-registry-and-binding-contract.md#L119)). Риск: разные поверхности будут по-разному трактовать “active/broken/pending”.
- Retry/failure semantics разорваны между документами: execution kernel и control-plane ожидают attempts/retries/failovers, но shared import-протокол не требует обязательного linkage `ImportRun <-> ExecutionRun/TraceArtifact` ([agent kernel](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/spec/runtime/agent-execution-kernel.md#L183), [control-plane spec](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/spec/operations/control-plane-configuration-and-observability-surfaces.md#L130), [PRT-040](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/plans/protocols/PRT-040-governed-content-source-processing-and-workflow-backed-import-substrate.md#L159)). Риск: “status есть, а диагностики причины нет”.
- Граница write ownership для privileged chat описана как bounded, но не зафиксирован единый command-envelope, который связывает chat actor с `Principal`/audit trail при мутациях ([PRT-039](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/plans/protocols/PRT-039-shared-control-plane-access-channel-and-management-substrate.md#L178), [auth spec](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/spec/security/auth-and-access.md#L41), [control-plane spec](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/spec/operations/control-plane-configuration-and-observability-surfaces.md#L160)). Риск: спорные “кто именно поменял состояние” в mixed bot/admin потоках.
- Есть дрейф между spec и runtime anchor по pipeline definition shape: в spec есть `status/pipelineDefaults/allowedCapabilities`, а в кодовом интерфейсе их нет ([pipeline-registry spec](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/spec/runtime/pipeline-registry-and-binding-contract.md#L76), [pipeline-registry.ts](/Users/deksden/Documents/_Projects/bot-platform/packages/core/src/runtime/pipeline-registry.ts#L1)). Риск: реализация будет домысливать critical behavior, который должен быть договорным.

# Что убрать/не вводить

- Не вводить chat-first approve/activate путь для imports: chat остается entry/status/toggle каналом, но не state-authoritative редактором governance ([PRT-040](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/plans/protocols/PRT-040-governed-content-source-processing-and-workflow-backed-import-substrate.md#L122)).
- Не вводить отдельные “приватные” state enum’ы для одного и того же `ImportRun` в каждом продукте без общей переходной карты на shared-уровне.
- Не вводить mutable no-code CRUD для pipeline definitions в первой волне; registry должен оставаться code-backed/read-only для surface selection ([pipeline-registry spec](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/spec/runtime/pipeline-registry-and-binding-contract.md#L243)).
- Не вводить второй validation path в UI/CLI поверх backend-контракта: это ломает единство write semantics ([control-plane spec](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/spec/operations/control-plane-configuration-and-observability-surfaces.md#L150)).
- Не вводить обязательную централизацию shared control-plane service/shared DB в рамках текущего цикла ([PRT-039](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/plans/protocols/PRT-039-shared-control-plane-access-channel-and-management-substrate.md#L200), [PRT-040](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/plans/protocols/PRT-040-governed-content-source-processing-and-workflow-backed-import-substrate.md#L149)).

# Что минимально добавить в протокол

- Добавить компактную shared transition-таблицу для `ImportRun` (с owner на каждый переход): минимум `created -> processing -> review_required -> approved -> activation_pending -> activated`, плюс failure arcs `processing -> failed`, `review_required -> rejected`, `activation_pending -> activation_failed`, и явный retry path.
- Зафиксировать минимальный handoff contract между workflow и product importer: обязательные input/output поля, idempotency key и error envelope для шага “bundle interpreted into product revision” ([PRT-040](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/plans/protocols/PRT-040-governed-content-source-processing-and-workflow-backed-import-substrate.md#L113)).
- Добавить обязательные linkage refs для observability: `import_run_ref`, `connected_source_ref`, `source_revision_ref`, `execution_run_ref`, `requested_by_principal_ref`, `approved_by_principal_ref`, `activated_by_principal_ref`.
- Добавить минимальный `PipelineBinding` state contract (например `draft/validated/active/error/disabled`) и rollback semantics при invalidated binding/pipeline deprecation.
- Явно расширить capability vocabulary (или добавить обязательный extension-point) для `import_run.start`, `import_run.review`, `source_revision.activate`, чтобы UI/CLI/chat/backend проверяли один и тот же access envelope.
- Добавить единый privileged-chat command envelope: обязательная principal resolution, capability check, target object ref, mutation intent и audit fields до применения write.
