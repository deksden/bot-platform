## Premature abstractions

- Отдельный “observability service” или “diagnostics product” для import/control-plane до того, как у shared substrate появились два реальных потребителя и стабилизированы базовые IDs/events/read models.
- Универсальный event catalog для всех будущих продуктовых нюансов поверх минимального framework baseline. Здесь нужен не новый мегасловарь, а дисциплина применения существующих canonical events к shared object lifecycles.
- Хранилище “сохраняем все raw payloads навсегда, вдруг пригодится”. Framework governance уже правильно настаивает на selective heavy capture, redaction и retention classes. См. [trace-artifact-governance.md](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/spec/runtime/trace-artifact-governance.md):55, [trace-artifact-governance.md](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/spec/runtime/trace-artifact-governance.md):113.
- Попытка сделать full-blown trace viewer или universal admin diagnostics UI раньше, чем формализованы minimal investigation read models и audit contracts по control-plane/import.
- Попытка стандартизовать product-specific report wording и import-review prose как часть shared observability canon. Правильный shared уровень здесь: lineage, identifiers, states, artifacts, auditability и bounded explanation envelope, а не единый текстовый шаблон для всех продуктов. См. [decision-explanation-envelope.md](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/spec/runtime/decision-explanation-envelope.md):31, [decision-explanation-envelope.md](/Users/deksden/Documents/_Projects/bot-platform/.memory-bank/spec/runtime/decision-explanation-envelope.md):148.
