## Пробелы и риски

- `PRT-039` и `PRT-040` пока не делают обязательным reuse уже существующего platform seam для pipeline registry и binding validation. Формулировки про “shared contracts + product-local implementation” правильные, но без явного cleanup task легко зацементируют нынешние копии вместо их замены. Это особенно заметно потому, что `bot-platform` уже держит generic registry utility (`/Users/deksden/Documents/_Projects/bot-platform/packages/core/src/runtime/pipeline-registry.ts:1-167`), но platform kernel все еще знает только `research_then_answer`, а не `docoved_answer` (`/Users/deksden/Documents/_Projects/bot-platform/packages/core/src/runtime/kernel.ts:3-21`, `/Users/deksden/Documents/_Projects/bot-platform/packages/core/src/runtime/kernel.ts:139-155`). То есть seam уже есть, но convergence task в протоколе пока недоформулирован.
- Hidden product integration глубже, чем протоколы сейчас проговаривают. SellerAgent по-прежнему держит `docoved_answer` как встроенную ветку своего conversation service и патчит туда Docoved-specific context (`knowledgeSourceRef`, snapshot, memory-bank paths, reply continuity) прямо из Seller composition root (`/Users/deksden/Documents/_Projects/seller-agent/packages/core/src/conversations/service.ts:923-1034`, `/Users/deksden/Documents/_Projects/seller-agent/packages/core/src/conversations/service.ts:1089-1177`). Если в backlog не появится отдельный cleanup на owner seam, эта интеграция переживет extraction и останется “hidden shared runtime”.
- Docoved residue уже не сводится к package.json зависимостям. В локальном `api-contract` и store-слое Docoved top-level control-plane поля по-прежнему несут Seller-flavored `businessProfileSlug` для `Channel` и `KnowledgeSource` (`/Users/deksden/Documents/_Projects/docoved-agent/packages/api-contract/src/operations.ts:1587-1678`, `/Users/deksden/Documents/_Projects/docoved-agent/packages/db/src/control-plane-store.ts:282-330`, `/Users/deksden/Documents/_Projects/docoved-agent/packages/db/src/control-plane-store.ts:629-685`). Дополнительно `docoved-answer-service` протаскивает `businessProfileSlug` рядом с `knowledgeSourceRef` в runtime context (`/Users/deksden/Documents/_Projects/docoved-agent/apps/api/src/docoved-answer-service.ts:119-154`, `/Users/deksden/Documents/_Projects/docoved-agent/apps/api/src/docoved-answer-service.ts:203-242`). Риск здесь не только naming-smell, а freeze accidental Seller residue into shared canon.
- Implicit server-only configuration paths пока описаны слишком мягко. Public Docoved binding still depends on env-only `DOCOVED_PUBLIC_KNOWLEDGE_SOURCE_REF` (`/Users/deksden/Documents/_Projects/docoved-agent/apps/api/src/docoved-public.ts:33-69`, `/Users/deksden/Documents/_Projects/docoved-agent/apps/api/src/index.ts:35-54`), а hosted runbook прямо признает, что без explicit env Docoved runtime defaults to selleragent domains (`/Users/deksden/Documents/_Projects/docoved-agent/.memory-bank/spec/operations/docoved-hosted-bootstrap-runbook.md:184-189`). С другой стороны, Seller `packages/shared` still mutates `process.env` while loading project helpers (`/Users/deksden/Documents/_Projects/seller-agent/packages/shared/src/business-profile-project.ts:331-380`). Для A06 это важный smell: shared-like behavior завязан на hidden server paths, а не на explicit contracts.
- `packages/shared` помечен как fake shared bucket, но в протоколах нет явного exit criterion. Сейчас bucket still owns `business-profile-project`, `business-profile-media`, `secrets`, `provisioning-policy` (`/Users/deksden/Documents/_Projects/seller-agent/packages/shared/src`), а ownership spec прямо говорит, что это migration bucket, а не legitimate long-term owner (`/Users/deksden/Documents/_Projects/seller-agent/.memory-bank/spec/project/business-profile-project-and-package-ownership.md:138-185`). Без task-level closure condition такой bucket обычно живет дольше всех.
- В Docoved package graph сохраняется прямой Seller ownership residue: `@selleragent/api-contract`, `@selleragent/shared`, `@selleragent/core` still sit in active Docoved packages (`/Users/deksden/Documents/_Projects/docoved-agent/apps/api/package.json:15-23`, `/Users/deksden/Documents/_Projects/docoved-agent/packages/core/package.json:14-20`, `/Users/deksden/Documents/_Projects/docoved-agent/packages/db/package.json:14-19`). Протоколы это называют, но пока не превращают в measurable “no-new / burn-down” rule.

## Что убрать/не вводить

- Не вводить новую product-local копию pipeline registry, validator или pipeline catalog. Для этого уже есть platform owner и generic utility в `bot-platform`; следующий шаг здесь extraction/convergence, а не еще один локальный helper.
- Не канонизировать `businessProfileSlug` как top-level shared field для `Channel`, `KnowledgeSource` или import/control-plane contracts только потому, что это поле осталось в Docoved compatibility layers. Это hidden Seller integration, а не trustworthy shared vocabulary.
- Не переносить в shared слой целиком текущие Docoved helpers вроде `/Users/deksden/Documents/_Projects/docoved-agent/apps/api/src/docoved-channel-binding.ts:7-111` или `/Users/deksden/Documents/_Projects/docoved-agent/apps/api/src/docoved-answer-service.ts:74-155`. Там смешаны product-kind checks, active-snapshot resolution, public-surface restrictions и raw-path compatibility fallback; это не generic substrate.
- Не оставлять `packages/shared` и pass-through ownership shims как long-lived “временное shared”. Особенно показателен `provisioning-policy`: ownership spec уже говорит, что generic primitive и Seller binding должны иметь разных владельцев (`/Users/deksden/Documents/_Projects/seller-agent/.memory-bank/spec/project/business-profile-project-and-package-ownership.md:162-184`).
- Не расширять env-driven transition paths как sanctioned target model: `DOCOVED_PUBLIC_KNOWLEDGE_SOURCE_REF`, raw `memoryBankRootPath` fallback, in-process env overrides in `sa-docoved` bridge (`/Users/deksden/Documents/_Projects/docoved-agent/packages/sa-docoved/src/legacy-in-process-acceptance-host.ts:74-102`) должны считаться exception seams, а не reusable base contracts.

## Что минимально добавить в протокол

- В `PRT-039` нужен явный cleanup item: product copies of `packages/core/src/runtime/pipelines.ts` must be replaced by one shared registry/use-site based on `bot-platform` pipeline-registry seam, с exit criterion вида “no identical pipeline catalogs remain in SellerAgent and Docoved”.
- В `PRT-038`/`W5` нужен отдельный cleanup task на `docoved_answer` inside Seller runtime: вынести его из Seller conversation composition root в explicit integration seam with one owner. Иначе hidden cross-product runtime останется жить вне declared package cuts.
- Нужен gate `no-new-cross-product-owner-leaks`: новые `@selleragent/*` зависимости в Docoved, новые `@docoved-agent/*` зависимости в SellerAgent, и новые product-specific top-level fields в shared/read-model contracts допускаются только как time-boxed exception с owner и removal target.
- Нужен отдельный backlog item на hidden config paths: заменить env-only public-source binding, selleragent-domain defaults и raw path compatibility на explicit bound-surface / bound-source contracts; все оставшиеся server-only fallbacks пометить transition-only и закрывать по очереди.
- Нужен exit criterion для fake shared bucket: `packages/shared` либо исчезает, либо в нем остаются только truly tiny generic utilities с явным owner rationale per module. Сейчас это не зафиксировано достаточно жестко.
- Нужна field-level extension policy для shared objects: product overlays должны идти через namespaced extension payload или явный product-local projection, а не через постепенное засорение top-level shared schema случайными полями из migration tails.
