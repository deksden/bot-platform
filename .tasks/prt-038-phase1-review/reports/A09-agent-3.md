## Что минимально добавить в протокол

- Добавить в `PRT-039` и `PRT-040` короткий обязательный раздел `Verification contour` с 4 слоями:
`unit`, `integration`, `workflow/lifecycle`, `scenario`.
- Добавить к каждому child protocol таблицу `flow -> acceptance anchors -> owner -> execution status -> must-run command`.
`PRT-039`: auth/access/binding/channel; `PRT-040`: import lifecycle/source processing/activation.
- Явно привязать `PRT-039/040` к `verification-matrix.md`, `scenarios/scenario-matrix.md`, `mbb/scenario-docs-guide.md`, `spec/scenarios/scenario-system-and-evidence.md` в `related_files`.
- Зафиксировать минимальный effective regression pack per wave:
W1 (control-plane) и W2 (governed-content/import), с явным списком must-run anchors до closure.
- Ввести минимальную failure coverage matrix для `PRT-039/040`: error/retry/auth/access/binding/import lifecycle, с ожидаемыми evidence fields.
- Зафиксировать rule: acceptance-critical anchors из этих протоколов должны быть `full scenario contract` и не оставаться indefinitely `planned`.
- Добавить reuse rule по fixtures/helpers: использовать named fixture profiles и существующие product readback/playbook команды; ad-hoc DB-read-only proof считать неполным.
- Прямо прописать “shared substrate verification without duplicating product packs”: shared checks остаются framework-owned только в части contracts/shell, product no-regression остается в product repos.
